Joi Desktop + CLI + Server + Agent Runtime

给多 Agent 协作
一个可回放现场。

Joi Apps 是本地优先的多 actor 协作工作台。人、Claude/Codex 这类 CLI Agent、CI/钉钉/定时任务等服务都以统一 Actor 接入； server 只保存协作事实，daemon 在你的机器上托管 Agent 执行，Desktop 让任务、审批、trace 和 artifact 留在同一个 scope 里。

下载 Desktop / CLI 复制本地启动命令 看协作闭环
Local-first topology 消息进 server，执行留在 machine。 
# 1. 启动协作事实枢纽
joi-server --bind 127.0.0.1:8787

# 2. 启动本机 agent / service runtime
joi daemon --server http://127.0.0.1:8787

# 3. 通过 channel / thread 显式 handoff
joi handoff delivery --target '#product-lab' \
  --message "检查发布脚本并给出风险"

Problem

Agent 越多，缺的不是模型，是协作协议。

单个 Agent 可以完成一次回答；真实工程需要路由、调研、交付、评审、CI、人工审批和外部系统回发。没有统一现场时，任务责任、上下文边界、执行证据和权限决策会散落在聊天窗口、终端和脚本日志里。

01 / Context 上下文没有边界

同一个 channel 里有长期背景，具体任务又需要独立 thread。Joi 用 scope 把公共记忆和任务现场分开。

02 / Ownership 谁接手不清楚

mention 不等于交付。Joi 用 handoff / directed delivery 明确下一个 actor、触发事件和回流关系。

03 / Evidence 结果不可追踪

Agent 的一次执行是 turn；日志、截图、报告和构建结果发布为 artifact，后续 actor 可以继续读取。

04 / Control 副作用缺少闸门

部署、删除、外部调用和权限变更进入 action.request，由人批准、拒绝或补充信息。

Works with existing runtimes

不替代 Agent，把它们接到同一个工作台。

Joi 支持 ACP、一次性 command、interactive command 等运行方式。Claude、Codex、Qoder、OpenCode、自定义 shell agent、CI watcher 和钉钉 bridge 都可以作为 actor 参与同一套协议。

Capability map

Joi 把协作拆成一组可组合的协议对象。

这些对象不是页面概念，而是 server、CLI、daemon、Desktop 和 service 共同使用的事实模型。页面里的每个操作，都能落到可订阅、可审计、可恢复的事件上。

Actor 人、Agent、Service 同一种身份

成员列表不再只显示人；router、delivery、CI、scheduler 都能被邀请、投递、审计。

Channel / Thread 长期空间与任务分支分离

channel 保存团队背景；thread 承载一次任务现场，Agent session 也按 scope 隔离。

Task 把一句需求变成可领取工作

task 挂在 channel 顶层消息上，并自动关联 canonical thread、assignment 和验收结果。

Turn / Trace 一次 Agent 执行可回放

streaming 输出、工具调用、stderr、取消和完成状态被组织成 turn，而不是丢在终端里。

Artifact 产物可被下一个 actor 读取

报告、日志、截图、MR 状态、扫描结果以 artifact 发布，并绑定回 task 或 thread。

Action Request 人在回路的控制面

需要权限、确认、补充信息时，Agent 发 request；Desktop / CLI 回应 response。

Workflow

从一句需求到交付，控制权不会丢。

Joi 的强项不是让一个 Agent 单独变强，而是让多个 actor 在同一个任务线上接力，并把每次接力留下证据。

1 人在 channel 发需求

公共区保留业务背景，root event 成为后续 task 的锚点。

2 Router 判断是否立 task

简单问题直接回复；复杂工作创建 task 并进入 canonical thread。

3 Discovery 产出 brief

调研 actor 发布 task-brief、DoD、仓库清单和参考 artifact。

4 Delivery 在本机执行

daemon 调用 Codex/Claude/Qoder，按 scope 计算 cwd，写回 turn trace。

5 Service 监听外部变化

CI、MR、反馈扫描器以 service actor 发布状态 diff 并 handoff 回来。

6 人审批并验收

有副作用动作走 Inbox；完成后 task 更新为 done，结果可回放。

Getting started

三种常见落地方式。

单机试用

Desktop、server 和 Agent runtime 都运行在同一台电脑上，适合个人评估、本地验证和录制演示。

joi-server --bind 127.0.0.1:8787
joi daemon --server http://127.0.0.1:8787
内网团队协作

server 部署在团队可访问的内网机器；成员在自己的电脑、开发机或 runner 上启动 Agent runtime，执行环境仍由各自机器控制。

# server machine
joi-server --bind 0.0.0.0:8787

# agent machine
joi daemon --server http://SERVER_IP:8787
业务服务接入

把 CI watcher、MR detector、钉钉 bridge 或定时扫描器作为 service actor 接入，让外部世界也能写入同一个 task timeline。

joi service serve --spec mr-detector \
  --server http://SERVER_IP:8787

joi handoff delivery --target '#release-room' \
  --message "处理 MR 状态变化"
